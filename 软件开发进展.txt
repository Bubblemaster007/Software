一、当前总体进展

当前为本地运行的研发预览版，已形成以课题2为主线的业务闭环：
工程建立 → 数据录入与校验 → 源荷分析及场景生成 → 事件嵌入 →
运行阶段和线路故障设置 → 平衡计算 → 策略调整复算 →
简化资源配置及复核 → 结果归档、比较、报告和备份。

已运行的主要能力：汇总逐时平衡、IEEE33及用户自定义辐射网平衡、
稳态交流潮流复核、连续设备故障与修复、条件多样本随机模拟、
多水平年源荷背景生成、工程及结果快照管理。

新增已接入：三级工程类型、逐设备工程台账与历史版本、11类典型场景及区域目标、
PPT需求指数/优先级计算、熵权-CRITIC-TOPSIS质效评价及66项需求追踪。
新增逐设备时序调度入口已读取台账版本并优化多节点源储、负荷和电气分区；
旧汇总平衡仍不自动替换。评价指标需真实来源，
动态校核与任务书性能仍未达标验收。

物理模型联合MILP，已替换源储菜单原先仅枚举试算的主入口；旧试算档案保留。

功能：
（1）查看当前源荷条数、本地数据校验、运行模型、阶段数量、故障及生产
     序列引用、当前工程的平衡档案数量。
（2）按六步操作流程进入数据、场景、计算、策略、规划及报告页面。
（3）加载本工程最近一次计算结果。
（4）编辑工程名称、区域和县域级/乡镇级/村级类型，兼容历史村镇级工程。
     初始化、保存、新建和切换期间禁用相关输入，防止异步读取覆盖新工程。
（5）顶部提供新建、切换、保存工程和备份已保存数据；切换前自动保存
     当前工程，保存和计算使用工程修订号检查版本冲突。
状态：基本工程工作流已实现；当前为本机工作空间，未建立多用户权限体系。

02 数据管理
二级菜单：阿拉山口资料、源荷时序、电网拓扑、电网节点、电网线路、源储参数、
电源台账、储能台账、负荷与保供目标、变压器与开关、二次设备与通信、经济参数。

2.1 阿拉山口资料
（1）扫描SourceData中的阿拉山口收资，提供原始文件目录与下载。
（2）读取冬、夏两份典型负荷Excel，兼容标题单元格的非标准null内容。
（3）原始负荷为5分钟采样；检查时间连续性、数值合法性和完整日样本。
     每小时12点算术平均生成24小时输入，次日零点边界不计入当日。
（4）原表未注明负荷功率单位；界面要求选择并核实MW或kW。
     MW转换为kW时乘1000，不自动认定原始单位。
（5）预览后应用到当前工程，解除旧故障场景及生产序列引用并清空旧阶段；
     原始路径、SHA256、单位假设和转换说明随工程及计算报告保存。
（6）没有同时间轴风光实测出力时暂填0，并明确标注为未配置出力。
（7）预览风场月发电量原表，保留万千瓦时口径；装机列标题与原始数值
     存在单位疑点，保留原值待核实，不直接生成逐小时出力。
（8）PDF、DWG、DOC作为原始参考资料下载，不自动推断真实线路阻抗。
状态：典型日负荷接入和资料查看已实现；实际网络参数仍需依据图纸、台账录入。

2.2 源荷时序
（1）CSV导入预览、前5行检查、取消和应用、当前CSV导出。
（2）手工建立逐时序列、从末条下一小时追加、逐格编辑与24条分页。
（3）检查表头、四列结构、日期、连续小时、空值、负值和非有限数，
     显示错误物理行号并支持跳转；本地校验后仍由后端复核。
（4）统一字段：timestamp,load_kw,wind_kw,pv_kw；功率单位kW，
     交互汇总计算支持2—8760小时，CSV文件入口限制2MB。
状态：已实现；与平衡模块共享当前工程源荷输入。

2.3 电网拓扑、电网节点、电网线路
（1）三个入口共用节点、线路和故障编辑工作区。
（2）可载入IEEE33示例草稿、新建阿拉山口录入模板、导入/导出网络JSON。
（3）节点支持增删、编号、名称、有功负荷kW和无功负荷kvar编辑。
（4）线路支持增删、编号、名称、首末节点、电阻/电抗Ω、投运/备用编辑。
（5）支持网络名称、数据来源、基准电压kV设置。
（6）草稿修改须“校验并应用网络”，再保存工程；应用后切换到节点网络模型。
（7）校验2—100节点、根节点1、唯一编号、合法端点、非负参数及正总负荷。
     投运线路须构成连通辐射树；拒绝自环、并联重复、环路和孤立节点。
     后端自动将树方向规范为从根节点向外。
（8）已应用网络显示示意拓扑、线路编号、风光接入点；非地理地图。
（9）点击线路或编号、勾选线路可设置/取消全时域故障；红色虚线标识故障。
（10）仅投运线路可选，故障编号不属于当前网络或重复时拒绝计算。
（11）网络随工程保存；计算另存网络快照，历史结果使用计算时拓扑。
（12）网络编辑已可填写逐线路capacity_kva；新增逐设备入口按该限额计算，
      留空采用本次缺省kVA限额。旧IEEE33入口仍使用统一kW限额。rate_a
      继续作为来源字段保留，不自动换算为容量。
状态：编辑、校验、故障点设置和交互计算已贯通。阿拉山口新建网络仅为
待录入模板，不能作为已经核实的实际示范网络。

状态：旧平衡参数已实现；当前储能、应急电源仍集中接根节点。新增逐设备台账

2.5 逐设备台账、分类目标与经济参数（新增）

储能保存位置、移动状态、功率能量、SOC上下限、效率、温度可用系数。
负荷保存类别、峰值/无功/曲线、最低保供比例、目标时长、可削减/中断和优先级。

台账可导入导出JSON，独立修订号检查、保留每一历史版本；按钮“保存台账”

配置复核/随机样本继承基准台账版本；旧平衡结果明确标记未使用逐设备约束。
状态：数据录入、校验、版本和追溯已实现，台账已进入逐设备MILP调度。
变压器当前仅为变比1理想支路容量；通信操作、移动道路行程、动态模型仍待接入。

03 保供场景生成
二级菜单：典型场景库、分类目标与优先级、源荷增长与极端窗口、近中远期全年背景、
故障与恢复场景、生产序列嵌入。

新增典型场景库：按完整65页中期PPT第14—15页提供西部县域2类、三区乡镇6类、
三区村级3类共11类模板；20/50年重现期不自动转换为逐时故障概率。区域保供
目标按第19页，基本保障西部72h/东中48h，居民功率60%/80%，支持应用到
负荷台账草稿并保存；均标识为未做地区校准。
新增分类目标与优先级：按第16—18页CTI分界与D/P公式计算分类、需求指数、
重要性和综合优先级，逐分项展示权重贡献；CTI采用已评审录入值。保留PPT
原公式1-R/Tmax方向，六权重非负且合计1，拒绝无效参考上限。

3.1 源荷增长与极端窗口
调用研究代码进行负荷增长、风光缩放、源荷特征、经验分位边界、压力窗口
评分及最高评分极端窗口提取。可预览源荷和合成天气、导出窗口快照、应用
增长序列或极端窗口，也可送入生产序列嵌入。输入变化后旧分析不得直接应用。
方法边界：窗口评分和合成天气不代表实测天气或灾害发生概率。

3.2 近中远期全年背景
按最多三个水平年分别设置增长、风光系数、扰动和随机种子，生成并归档
全年背景；支持下载全年源荷、分级负荷、负荷及新能源经验边界、分解结果。
方法为滚动均值近似分解、经验分位和月份/小时独立重采样；每水平年固定
8760小时，闰年截断末24小时，缺少月份时回退全样本。
方法边界：不是VMD、Res-GRU或WGAN的已训练实现。

3.3 故障与恢复场景
支持两类设备状态场景：
A. 风速脆弱性逐小时独立状态抽样，设置设备类型、额定容量及脆弱性参数。
B. 连续故障与修复，设置每小时失效率λ、整数修复小时、额定容量和种子；
   故障转移概率为1-exp(-λ)，修复期间保持故障状态。
场景按工程归档，应用时严格匹配源荷时间轴，作为资源可用容量上限进入平衡。
此入口的资源设备故障与线路支路故障为不同设置；支路故障在网络/阶段中配置。
方法边界：参数是研究假设，尚未用阿拉山口实测故障记录完成区域校准。

3.4 生产序列嵌入
将极端源荷事件按起始小时嵌入背景，可选择边界平滑。可绑定同工程且与
事件时间轴一致的故障场景，同步重定位事件容量，事件外按生成时资源容量
恢复；容量不做平滑。保存背景、事件、参数、生成时序和事件标记，支持
历史查看、应用与JSON导出。计算校验生产序列与输入CSV一致，并保留来源。
方法边界：负荷可达性目前按1处理，未建立联合概率与移动资源到位模型。

04 承灾极限分析
二级菜单：分析设置、承灾边界、薄弱环节。
现有功能：冻结工程、台账、网络和调度参数，设置强度/时长、事件起点、样本、
种子、成功判据与脆弱性；逐样本调用实际逐设备MILP，不再使用结果占位框架。
脆弱性支持电源、储能、线路、变压器、开关、外部供电；输入参考强度、参考
时长、事件失效概率、形状、修复时长、故障后可用率、共因组和参数来源。
参考概率转换恒定小时风险率，再按dt抽样。故障步首发生、修复向上对齐网格，
灾害结束不自动清除未修复故障，修复后可再次失效；不将重现期当逐时概率。
同组共享均匀冲击、不同组独立；PCG64与目标/组名SHA256键固定随机数。
强度0不触发本机制，基准检修/故障保留，不能让备用或常开线路误投入。
成功判据可选逐负荷分类目标或总未供电量预算（含主动削减），参数冻结。
输出经验成功比例、逐点Wilson保守/乐观区间、未知计数、已测达标强度集合、
最大已测达标强度、右侧未封闭和非单调提示；无达标证据时不生成虚构零极限。
未知/未测样本不剔除；时域不足不认定完整目标通过；限时可行解若不达标不能
证明不可行；超时未获可行解的样本记未知。Wilson不保证全边界同时置信。
薄弱性：在选定工况（页面默认最大强度/时长）逐目标移除脆弱性机制，保留其他
冲击及原有检修；按两次均完成分层优化的配对避免未供电量排序，保留负值及
标准误，未测或求解不完整目标继续显示。不是全灾种通用设备重要度。
范围：最多50强度×20时长、每点1—1000样本，扫描加对照合计≤5000次；
15/30/60分钟、最长168小时，受当前2—100节点逐设备模型及变量数限制。
总时限1—3600秒，超时保留全部工况表并标不完整；最差样本保留扰动、汇总
轨迹与负荷校核，全部样本提供CSV，完整输入/版本/摘要与结果提供JSON。
方法边界：扰动与基准可用率取最小值；外部供电按有功容量比例降额；储能
故障只限制功率，未模拟能量损毁。当前无损LinDistFlow、不含动态/涌流/通信。
状态：条件扫描及设备对照已实现；地区校准、加权场景集、自适应搜索、全部
临界时长/设备强度指标及动态联合验证待完善，不宣称真实系统全局承灾极限。

05 电力电量平衡
二级菜单：模型与资源、运行阶段、逐设备时序调度、随机生产模拟、逐设备年度滚动、平衡结果、
网络逐时结果、原生年度流水线。

5.1 运行阶段
可设置最多20个阶段的名称、累计结束小时、电网和应急电源可用比例及故障线路。
阶段名去首尾空格后须非空且唯一，结束小时严格递增并覆盖全部时序。
启用阶段后，各阶段故障替代全时域故障；阶段故障空列表表示该阶段恢复。
SOC连续传递，按阶段输出缺供、弃电等统计；阶段不是建设水平年。

5.2 模型与资源
A. 汇总逐时平衡：2—8760小时，调用研究代码功率/电量平衡算法。
B. 节点网络平衡：2—168小时，采用已应用自定义辐射网，未配置时为IEEE33。
   总负荷按节点基准负荷比例分配，关键/重要/一般负荷按比例保障；
   风光可设置接入节点，储能、应急和外部电源接根节点。
   采用LinDistFlow线性规划调度，交流网损反馈迭代和交流潮流复核。
   可设置统一支路容量、电压上下限及线性调度保护阈值。
   只计算根节点连通区域，不模拟故障后独立孤岛供电及动态稳定。

5.3 平衡结果
保存计算输入、参数、工程版本、阶段、故障场景、来源和算法版本。
展示缺供/弃电时段比例、最大缺额、缺供/弃电电量、分级负荷满足情况、
阶段指标、孤岛支撑需求与极端事件小时数等指标。
图表支持供需平衡、资源出力、储能SOC及网络交流电压视图和时间缩放。
逐时结果支持CSV，完整计算报告支持HTML导出。
口径边界：单轨迹“缺供时段比例”不表示经校准的地区灾害发生概率；
孤岛支撑需求只表示外部供电不足或根节点失联的需求提示。

5.4 随机生产模拟
以已归档基准为依据，对一种资源故障进行2—20个等权样本连续故障抽样，
每样本支持2—168小时，复用汇总或节点网络模型、阶段与网络快照。
保存样本种子、场景、计算结果和批次，输出均值、P95、缺供样本比例、
Wilson 95%区间、分阶段统计以及网络电压和网损汇总，可导出样本CSV。
方法边界：源荷和阶段固定，是给定假设条件下的样本统计，不是完整区域风险模型。

5.5 网络逐时结果
按时刻查看故障支路、根节点连通性、节点负荷与供电量、线性节点电压和
支路有功潮流。历史结果优先使用已保存网络快照。交流极值由交流电压曲线
独立展示，线性电压与交流校核不能混用；旧档案缺失字段不补造数值。

5.6 原生年度流水线
独立后台进程调用课题2原生下游流程，支持2—8760小时扩展CSV及任务ZIP。
输入除源荷外还含event_id、wind_speed，可选资源容量、失效率、修复时长等。
常规event_id为-1，事件须满足当前原生协议的连续36小时结构。
任务记录排队/运行/成功/失败/中断状态、进程身份、日志及输出文件。
与交互入口的区别：该流程固定IEEE33研究网络，尚未接通自定义阿拉山口
网络；输入与故障参数需符合原生协议，不能直接视为任意交互工程的全年计算。

5.7 逐设备时序调度（新增独立入口）
读取已保存工程网络与指定台账历史版本，支持1/5/15/30/60分钟、最多672步且
最长168小时、建模上限20万变量。1分钟最多11.2小时，5分钟最多56小时；
15分钟及以上仍同时受672步和168小时约束。各设备曲线须为1个常值或与步数一致，数组首项
对应本次开始时间，不隐式截断/重采样；风光水缺曲线拒绝计算，不补额定出力。
采用稀疏MILP：逐节点P/Q平衡、平方电压LinDistFlow、逐线路kVA视在功率
内接八边形保守限额、源储无功能力与可选视在额定容量。
按基本保障/居民生活/一般负荷，先分层最小化分类目标缺额，再分层最小化
非计划缺供，最后减少研究运行成本；不是用成本高低覆盖已固定的高优先目标。
电源最小出力、启停与启动延迟、爬坡、到位、可运行时长、燃料电量上限生效。
柴油机/发电车须有燃料电量或可运行时长，不能默认为无限燃料；已知燃料为0
的燃料机组不能以零出力启动并提供建压。
储能充放互斥、逐设备SOC/效率/温度系数及跨时段能量守恒；移动到位后才参与。
构网条件：外部供电不可用的电气分区须有可用构网电源/储能；初始未带电时
须有黑启动条件，跟网型风光不能自建电压频率。构网储能按有效额定能量、
燃料机组按参考可发电量预留显式比例，也可给定正的绝对构网储备。默认参考量取
台账初始声明、窗口初始实际库存与最大单次补给量的最大值，储备与时间步长独立。
逐设备可用系数和线路0/1状态支持常值/逐步数组；常开开关默认为断开，
显式线路状态可下达闭合，但故障开关/变压器不可导通；每步只接受辐射森林。
计划负荷削减须显式开启，按最大可削减比例限制，和非计划缺供分别统计。
逐负荷输出连续目标保供、最大目标中断与目标判定。时域不足目标时长时，
未观察到失败也标为未完成校核。新增“强制满足台账保供目标”开关，默认关闭：
开启后禁止中断的负荷每步达标，允许中断的负荷用精确线性时钟限制最大连续中断；
须覆盖完整目标时长，不可行不生成方案。主动削减低于最低保供比例仍计中断；
另报累计中断，非累计预算。最后一步按目标窗口交集计时，零目标需求结束中断段；
步内沿用分段常值网格。事件前史可通过衔接参数提供，默认初态从新事件起点计。允许中断预算
若大于等于整个窗口，整段缺供也可能满足该判据，不等于持续保供。负荷移峰/转移仍待。
输出分层求解状态、达到时限时的可行解状态、变量/约束、原始约束和整数残差，
并检查逐时守恒。可显式强制电源启停、节点带电和带电负荷最低供电比例；
黑启动据此验证真实操作指令，不让调度自动略过不可行指令。旧请求默认不附加。
保存输入、工程/台账/网络版本、软目标算法devices.radial.horizon-milp.v3、硬目标v4、衔接/补给v5
及运行构建摘要，支持历史重开、逐时CSV和完整设备JSON；图表用阶梯线表示
分段常值，不在两个采样点之间暗示资源提前投入。
方法边界：全时域已知曲线的确定性研究调度；本入口不含交流网损、非线性
潮流、离网动态稳定、励磁涌流与实际通信操作。变压器只支持统一基准/变比1；
未含未提供的启动辅助电量和空载耗油。购电/充放电吞吐/启动成本为显式研究
参数，不能解释成地区核定价格或全寿命经济性。逐设备后台任务已接通；
年度滚动已复用本逐设备模型；旧随机入口仍待统一。


5.8 跨窗口初态与补给
逐设备页面增加“跨窗口状态与可发电量补给”，可输入初态JSON，或从已归档结果
选定时刻之后载入边界状态。导出接口为/api/device-dispatch/{id}/continuation，
committed_steps指定实际提交的前缀步数。文件包含来源记录、原输入摘要、工程与台账版本。
跨窗口状态包括机组前一时刻运行/有功、未完成启动的剩余步数、剩余可发电量、
已用运行小时、储能实际电量、已带电节点、连续中断尾段、历史最大及累计中断。
start推进到后续开始时刻，elapsed_hours记录距同一事件起点的已逝时间。资源到位
与负荷目标继续沿用原事件起点。曲线首项需对齐新的开始时刻，后续曲线由本次输入提供。
边界文件保留原步长与候选纳入设置。剩余启动量以步计，改变网格时需重新核对
剩余启动时间与补给数组。直接衔接采用相同网格，源储实际能量和已用运行小时连续。
补给按步开始生效，单位kWh，常值表示每步补给。已执行部分已进入末状态库存，
后续补给需重新填写。燃料引入逐步状态变量和守恒等式，矩阵随时间步线性增长。
完整中断前史通过prior_target_history_complete声明，尾段、历史最大和累计分别传入。
已知前史失败继续影响完整目标判定。前史不足时，软目标保留未校核，配置与硬目标
要求完整前史。当前窗口新增中断量另列，供后续年度统计衔接。
显式构网燃料储备在导出中保持固定。初态含源记录与摘要的参考说明，历史文件
按其原快照读取。当前台账修改后，历史导出继续使用原台账版本。
全停电恢复入口沿用从新事件冷启动生成操作序列的模型，延续初态通过逐设备入口使用。
状态接口已用于年度滚动任务，真实完整年度数据和项目规模验证继续接续，
原固定IEEE33年度流水线继续提供现有功能。空载耗油、启动辅助
能量、完整多电压交流与动态过程仍需相应设备参数和模型支持。

06 保供能力提升
二级菜单：策略库、资源调整、效果对比。
（1）基于平衡指标调用八项规则策略：关键负荷刚性保供、重要负荷有序保障、
     一般负荷弹性调节、储能快速功率支撑、长时电量保障、应急发电持续保供、
     移动资源应急支援、源储荷孤岛协同运行。
（2）展示是否触发、原因和配置建议，阈值沿用研究代码默认值。
（3）调整储能功率/能量、应急电源、外部供电、初始SOC及风光出力系数，
     复用基准时序、阶段、故障、网络位置与约束进行真实平衡复算。
（4）结果独立归档，绑定基准编号，比较缺额、电量和关键负荷满足情况。

07 源储协同配置
二级菜单：候选资源、目标与约束、规划阶段、配置结果。
当前主入口为多阶段源储机会约束配置，旧/api/planning枚举接口和旧档案保留，
不是把旧枚举结果改名为正式优化。新方法为
investment.multiperiod.weighted-joint-chance-milp.v3。
（1）从未建设电源/储能台账选择固定设备块或连续定容，混合优化位置、容量和
投运年份。台账功率/能量为参考上限，连续比例在0—1内，正的最小比例至少0.0001；
可设上下比例。储能功率/能量独立决策，可设最短/最长额定时长（E/P，默认最短0.25h
是可修改研究约束，不是厂家事实）。每ID最多投运一次，追加/替换用独立ID。
连续电源的可用曲线、最小出力、无功/视在功率、爬坡按功率比缩放；启动时间、
效率和可运行小时不缩放。燃料默认使用安装后的台账固定库存，也可显式选按功率比
缩放。储能SOC/构网储备按实际能量计，充放电/无功/视在上限按实际功率计。
容量比例与构网支持二元变量的乘积采用精确线性包络，未安装没有免费能量/建压。
连续储能须分别提供满额功率/能量投资与非零维护费分项，不自动按总价拆分；
固定建设费/固定年维护费按安装0/1计。厂家规格及线性参考技术假设仍需工程确认。
（2）建设阶段必须年份连续，输入阶段预算、相对基准负荷系数和代表事件年频次；
所有场景共享建设决策，不能根据已知故障为各样本单独建设。后验运行按场景调度。
（3）自动按候选/已有设备退役年拆分运营期，后期资产不提前使用，过期不继续
供电。每个事件内保持燃料、SOC、启停、到位、爬坡和节点P/Q、容量/电压约束。
（4）候选未投运时，功率、初始储能电量、无功及构网均被激活变量约束为0。
复用逐设备模型构建器，不以汇总功率缺额替代真实接入位置与网络故障效应。
（5）训练轨迹权重须为正且和为1；支持各运营期内的负荷/时段联合机会约束，
或跨全部运营期的联合机会约束，不用各期边际概率相乘代替跨期联合。
保供判据可选“目标窗口内每步达标”（默认）或“台账最大连续中断预算”。后者
在同一场景成功指标内约束全部保护负荷的中断时钟；时域均须覆盖完整目标，
每步模式更严格。其他负荷仍参与物理平衡与缺供损失计算。
（6）场景支持网供、源荷曲线、设备可用率、线路状态及储能温度系数，按建设
年份部分覆盖。设备映射按ID合并，覆盖另一设备不会意外清除原有故障。
温度系数同时降额功率和能量，表示事件初始温度条件，不模拟事件中热状态变化。
阶段覆盖字段省略或null表示继承，跨进程冻结JSON重读仍保持该语义；字典按设备ID
合并。本轮修正了默认值展开导致负荷系数被覆盖的问题。旧档案保留原显式冻结值，
若已包含展开默认值，须人工核对后新建输入，不倒改旧结果或静默改写旧快照。
（7）经济目标为期初投资+期末运营/维护折现净成本；可显式计线性剩余寿命残值。
含燃料、购电、吞吐/启动、主动削减与分类缺供损失。全局年维护费作为固定开销，
已有逐台维护随退役停止，候选维护另列，输入时须避免重复计价。
年频次×事件时长≤8760；不自动把灾害样本按8760倍外推。若缺正常运行样本，
不能称完整全寿命成本。每代表事件独立初始SOC和燃料，不跨事件/年份结转能量。

三、技术架构与代码组织

1. 运行方式
Windows本地部署；启动软件.cmd/启动软件.ps1启动本机Python服务，
浏览器使用启动器返回的当前构建地址（无旧服务时通常为8765）。启动脚本读取

旧服务占端口时在8765起的51个候选端口中启动新版本，不停止已有进程。
脚本等待API版本就绪后再打开页面，支持-NoBrowser只输出当前版本地址。

图纸/台账人工核实节点与线路 → 网络草稿编辑 → 辐射树校验 → 工程保存。
当前阿拉山口已接入典型日负荷；真实网络端点、阻抗、负荷分配及逐时风光
仍需补齐，不能用录入模板替代真实工程模型。

路线2：源荷与极端场景
历史源荷 → 增长与经验边界/全年背景 → 压力窗口评分 →
设备独立或连续故障 → 同时间轴源荷-容量耦合 → 极端事件嵌入 → 冻结生产序列。
后续需引入实测气象、区域故障校准、时间相关性和源荷-灾害联合概率。

路线3：电力电量与网络约束
工程输入及参数 → 引用/版本检查 → 阶段及故障映射 → 可用容量限制 →
汇总调度或LinDistFlow调度 → 交流网损迭代与稳态电压校核 →
逐时/阶段/全时域指标 → 条件多样本统计 → 保存报告与结果快照。
当前交互网络限制168小时；全年固定IEEE33另走独立原生任务流程。

路线4：保供提升与旧配置试算
基准平衡 → 八项策略规则 → 固定资源参数调整复算 →
简化资源组合枚举 → 推荐新增量 → 真实时序/网络复核 → 同条件效果比较。
新多期机会约束与连续定容另见路线7；旧策略尚需与逐设备入口统一；厂家规格校核、
自适应投资、移动路径及一二次设备联合配置仍待完善。

路线5：承灾与薄弱性
冻结台账/网络/调度 → 参考事件概率换算小时风险率 → 同键随机冲击/修复状态
→ 多强度/时长逐设备MILP → 目标或未供电量判据 → 未知保留和逐点区间
→ 已测边界/非单调 → 移除单设备机制的配对复算 → 任务归档和CSV/JSON。
条件等权样本不是地区风险概率；联合权重、动态与全边界同时置信待完善。

路线6：黑启动工程恢复
冻结全停电工程/台账 → 重要度及电气距离/初始功率预匹配 → 启动/合闸/投入
候选 → 人工队伍/独立分区并行调度与通信供电检查 → 同步外部数值/励磁容量
包络 → 全时域带指令MILP复算 → 保留可行前缀/拒绝失败候选 → 拓扑与时间
回放、恢复指标和归档。动态未校核明确保留，不生成实际安全许可。

路线7：多阶段源储配置
未建设固定块/连续容量上限/已有库存 → 分项价格及固定费用 → 连续建设阶段及预算
→ 共享投运、功率/能量比例与寿命激活变量
→ 自动退役分段 → 带权未来轨迹的逐设备物理模型 → 时期内或跨期联合机会约束
→ 折现投资/运营/维护/残值MILP → 整数、预算、实际概率与现金流核对
→ 独立输入样本外验证 → 选址、投运及概率/现金流/报告归档。
未建源储不贡献功率、初始能量、无功或建压；验证失败不因经济指标好而被忽略。

路线8：其他课题算法集成
模块输入输出协议 → 工程及基准快照 → 摘要校验 → 注册真实适配器 →
返回算法版本、指标和逐项校核证据 → 独立验证 → 结果归档。
离网和黑启动需动态及控制模型，不能从稳态潮流直接推导结论。
