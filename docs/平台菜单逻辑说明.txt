末端保供平台菜单层级与导航逻辑说明
版本日期：2026年11月20日
适用对象：当前本地研发预览版。
编制依据：软件当前 navigation.ts、App.vue 及对应页面组件；本文件描述实际界面关系，不将菜单存在等同于算法已经验收。

一、层级定义与阅读方法

1. 一级菜单：左侧编号01—11的业务工作空间。
2. 分组标题：数据管理、电力电量平衡中的非点击分类标题。用于说明所属关系，不是独立页面。
3. 功能菜单：左侧可点击的具体入口。无分组时直接隶属于一级菜单；有分组时隶属于对应分组。
4. 页内标签或模块：功能入口内部的细分内容，例如电网拓扑内的节点编辑与线路编辑。这些内容不再作为同级左侧菜单。
5. 操作按钮：导入、保存、生成、计算、应用、导出等，执行当前页面动作，不构成新的菜单层级。

因此，数据管理可理解为“一级业务 → 分类分组 → 功能入口 → 页内内容”；其他大多数业务为“一级业务 → 功能入口 → 页面内容”。分组标题与可点击菜单不能混为同一层。

二、完整菜单树

01 工程工作台
   ├─工程概览：当前工程准备状态、输入引用、归档结果数量。
   ├─操作流程：核心业务步骤与业务跳转按钮。
   └─工程信息：工程名称、区域、类型等。
   关系：三个入口是同一工作台页面的三个位置，点击后滚动定位。

02 数据管理
   ├─资料接入【分组】
   │  ├─阿拉山口资料：原始资料目录、单位核实、预览、应用和下载。
   │  └─源荷时序：CSV接入与校验、风光荷趋势图、逐小时编辑。
   │     ├─趋势图范围：全部时段／连续一周／连续一天【查看选项】
   │     └─逐小时数据编辑表【按需展开】
   ├─网络模型【分组】
   │  ├─电网拓扑
   │  │  ├─拓扑与故障【页内标签】
   │  │  ├─节点编辑【页内标签】
   │  │  └─线路编辑【页内标签】
   │  ├─变压器与开关
   │  │  ├─变压器【页内子项】
   │  │  └─开关【页内子项】
   │  └─二次设备与通信
   │     ├─控制器【页内子项】
   │     ├─自动化终端【页内子项】
   │     └─通信链路【页内子项】
   ├─设备与负荷【分组】
   │  ├─电源台账
   │  ├─储能台账
   │  └─负荷与保供目标
   ├─参数配置【分组】
   │  ├─源储参数：汇总平衡使用的统一资源参数。
   │  └─经济参数：成本等配置参数。
   └─数据治理【分组】
      ├─地理与灾害
      └─数据版本管理
   关系：每次选择具体入口，显示对应内容；页面路径显示“数据管理／所属分组／当前入口”。页内导航只列当前分组的功能入口，并与左侧选中项同步。
   电源台账、储能台账、负荷与保供目标分别显示对应内容；不再归入统一的“工程设备与分类保供目标”页面标题。
   注意：多类台账底层仍共用工程台账及版本，页面分类不代表数据库彼此独立。源储统一参数与逐设备台账也是不同的计算输入口径，不自动相互替代。

03 保供场景生成
   ├─典型场景库：预设场景模板的查看与配置。
   ├─分类目标与优先级：负荷分类目标及优先级设置。
   ├─源荷增长与极端窗口：增长分析与事件窗口选择。
   ├─近中远期全年背景：不同水平年的源荷背景研究。
   ├─故障与恢复场景：设备故障模型、参数、生成结果与应用。
   └─生产序列嵌入：把事件嵌入生产序列并应用。
   关系：左侧入口与页面标签对应，点击切换当前内容；页面顶部保留场景配置与计算流程说明。
   “典型场景库”属于输入模板，不是已运行的平衡结果。生成、保存、应用和平衡计算是不同动作；仅选择菜单不会运行后端计算。

04 承灾极限分析
   ├─分析设置：强度、持续时长、故障与修复等研究参数。
   ├─承灾边界：查看任务结果中已扫描的承灾边界。
   └─薄弱环节：查看对应分析结果。
   关系：同一承灾研究工作空间中的输入与结果视图，共享研究任务上下文；结果依赖实际提交与完成的任务。边界仅限已扫描范围。

05 电力电量平衡
   ├─输入设置【分组】
   │  ├─模型与资源
   │  │  ├─输入时序与风光荷趋势图
   │  │  ├─CSV原始数据与编辑【按需展开】
   │  │  └─资源参数、接入节点与故障设置【按需展开】
   │  └─运行阶段：阶段名称、结束小时、资源可用比例与阶段故障。
   ├─计算分析【分组】
   │  ├─逐设备时序调度【页内折叠模块】
   │  ├─随机生产模拟【页内折叠模块】
   │  └─逐设备年度滚动【页内折叠模块】
   ├─结果查看【分组】
   │  ├─平衡结果
   │  │  ├─最大功率缺额、累计缺供电量等指标
   │  │  ├─供需平衡／资源出力／储能SOC／网络电压【图表查看标签】
   │  │  ├─分阶段指标与逐时明细
   │  │  └─CSV与报告导出【操作】
   │  └─网络逐时结果：网络模型计算后的逐时网络结果。
   └─专项研究【分组】
      └─原生年度流水线【页内折叠模块】
   关系：所有入口属于同一个长页面，实际模块顺序与上述树完全一致。左侧与页面导航使用同一菜单定义；点击定位相应模块，并展开对应计算模块。逐设备年度滚动不单独分页。
   “模型与资源”入口对应输入时序和资源参数两块内容；“运行阶段”是后续单独模块，不属于资源参数折叠框。
   各计算模块具有自己的输入、任务及结果；“平衡结果”主结果区展示汇总／网络平衡计算结果，不是所有后台任务结果的统一容器。逐设备、随机模拟、年度滚动的任务结果应在各自模块查看，统一任务状态可到“系统与接口／计算任务”查看。
   图表中的网络电压选项仅在网络模型结果存在时显示。没有结果时对应区域显示提示，不代表计算失败。

06 保供能力提升
   ├─策略库
   ├─资源调整
   └─效果对比
   关系：同一策略工作空间的三个模块，左侧点击滚动定位；以已加载平衡结果为分析基础，调整后复算与对比。

07 源储协同配置
   ├─候选资源
   ├─目标与约束
   ├─规划阶段
   ├─一二次协同规划
   ├─灵活组网
   └─配置结果
   关系：同一配置研究工作空间的不同内容视图，按左侧所选入口显示。候选、约束与规划阶段属于输入；配置结果属于任务输出。一二次协同规划、灵活组网的入口保留其研究范围及待完善边界，不能仅凭菜单名称认定完整算法已交付。

08 离网稳定判别
   ├─判别对象
   ├─扰动与阈值
   └─风险结果
   关系：同一预留模块的对象、参数及结果框架。当前动态方程、训练权重和时域验证数据尚未交付，保留待对接状态；该层级不表示已有经验证的动态稳定判别结果。

09 黑启动路径优化
   ├─恢复分区
   ├─启动资源
   ├─一二次约束
   └─恢复序列
   关系：同一恢复研究工作空间的设置与结果视图。前三项设置分区、可启动资源及操作约束；恢复序列查看任务输出及回放。现有工程研究预案与静态复算不等同完整启动暂态或安全执行许可。

10 方案与报告
   ├─计算档案
   ├─方案对比
   ├─配置方案
   ├─质效评价
   ├─示范区实证
   └─成果与交付
   关系：前三项属于同一档案／报告页面，点击滚动至相应模块；后三项切换到各自专门内容页面。计算档案是已保存结果入口，与计算参数输入页面不同。加载某次平衡档案后会进入“电力电量平衡／平衡结果”。

11 系统与接口
   ├─计算任务：后台任务状态与管理。
   ├─功能规划与验收：需求及开发状态追踪。
   ├─接入清单
   ├─算法接口
   └─交接任务
   关系：前两项为独立内容视图；后三项位于同一接口工作空间内，通过滚动定位。接口接入与交接状态不代表相关科研算法已完成。

三、全局操作与业务菜单的区别

顶部“工程选择、新建工程、保存工程、备份已保存数据”为全局工程操作，作用于当前工程或本地已保存数据，不是数据管理或计算分析的下级菜单。
页面标题显示当前一级业务；数据管理的路径进一步显示分组和具体入口。页面按钮“生成”“计算”“应用”“导出”等为操作，不应在菜单树中再增加一级。
切换一级业务通常默认选择该业务第一个入口；点击同一业务的具体功能入口则更新选中项并切换内容或定位模块。切换菜单本身不会自动运行计算。

四、推荐业务顺序与数据流

工程工作台建立／选择工程
 → 数据管理准备并核实源荷、拓扑、设备及参数
 → 保供场景生成设置模板、增长、事件与故障参数，生成后主动应用
 → 电力电量平衡设置模型与阶段，选择合适计算模块并运行
 → 查看对应模块结果，必要时进入承灾极限分析
 → 保供能力提升调整策略／源储协同配置开展规划
 → 方案与报告查看归档、比较和导出。
系统与接口贯穿上述流程，提供任务管理和算法交接。
离网稳定判别、黑启动路径优化与数据、台账和研究任务有关联，但不要求用户在普通平衡计算前必须完成这两个模块。

五、维护规则与当前边界

1. 菜单改名、归组、排序、分页方式或页内标签发生变化时，同步修改本文及软件开发进展.txt。
2. 一级菜单、分组标题、功能入口、页内内容、操作按钮应分别描述，避免把输入、计算与结果误列为同一类对象。
3. 当前实现同时使用内容切换和长页定位，尚未全平台统一为同一种分页方式；本文分别注明实际行为。
4. 8760小时展示例为合成数据；能够显示全年曲线不表示所有计算模型都支持全年网络计算。各模型仍遵守各自时长和规模限制。
5. 本次仅编写当前菜单逻辑说明，不调整菜单或算法。
